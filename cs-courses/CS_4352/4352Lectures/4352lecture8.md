## **Heuristic Evaluation and Nielsen's 10 Usability Guidelines**

---

### Overview of Heuristic Evaluation

Heuristic evaluation involves using a set of guidelines to assess and improve design quality. Developed by Jacob Nielsen in 1994, this method requires several evaluators to independently review a system using established heuristics. This approach is particularly valuable before conducting user testing, as it allows for identification and correction of issues without wasting valuable user resources.

### Comparison with Usability Testing

- Heuristic evaluation: Faster, provides specific guidance on what to fix
- User testing: More accurate as it involves actual end users
- Optimal approach: Use heuristic evaluation first, then conduct user testing
- Recommended number of evaluators: 3-5 (five evaluators typically find ~75% of usability problems)

### Nielsen's 10 Heuristics

1. **Visibility of system status** - Keep users informed about what's happening through appropriate feedback (progress bars, space indicators, confirmation messages)
2. **Match between system and real world** - Use familiar language and concepts that users understand rather than technical jargon
3. **User control and freedom** - Provide clear navigation paths, undo/redo functionality, and back buttons
4. **Consistency and standards** - Maintain consistent layout, button placement, and terminology across all pages
5. **Error prevention** - Design systems that prevent errors before they occur (validation, confirmations)
6. **Recognition rather than recall** - Make options visible so users don't have to remember information between screens
7. **Flexibility and efficiency of use** - Provide multiple ways to complete tasks and shortcuts for expert users
8. **Aesthetic and minimalistic design** - Keep interfaces simple and focused on essential elements (like Google's search page)
9. **Help users recognize, diagnose, and recover from errors** - Provide clear error messages with constructive solutions
10. **Help and documentation** - Offer searchable help resources with step-by-step instructions

### Application

These heuristics will be used to evaluate class B projects, allowing for critique and improvement before user testing begins.

## **Heuristic Evaluation and Severity Ratings in UI Design**

---

### Severity Rating Scale

- Scale ranges from 0-4 based on four factors:
  - How common is the problem
  - How easy it is for users to overcome
  - Whether it's a one-off or persistent issue
  - How seriously the problem will be perceived
- Rating breakdown:
  - 0: Not a usability problem
  - 1: Cosmetic problem (fix only if extra time available)
  - 2: Minor usability problem (low priority)
  - 3: Major usability problem (high priority)
  - 4: Usability catastrophe (must fix before release)

### Heuristic Evaluation Process

1. Evaluators are given the usage scenario
2. Evaluators review the interface and assign severity ratings
3. Debriefing with design team to discuss findings
4. Team decides which issues to address based on severity and effort required

### Factors Affecting Severity

- Frequency: How often the problem occurs throughout the interface
- Impact: How difficult it is for users to overcome
- Persistence: Whether the problem is one-time or recurring
- Resource considerations: Time and effort needed to fix versus severity

### Examples Provided

- Issue: Users unable to edit weight in an app
  - Severity: 2 (minor)
  - Violated heuristic: User control and freedom
- Issue: Inconsistent button styles across application
  - Severity: 3 (major)
  - Violated heuristic: Consistency and standards

### Advantages and Disadvantages

- Advantages:
  - Fast, quick, and inexpensive process
  - Provides early insight into usability problems
- Disadvantages:
  - Difficulty finding trained usability experts
  - May identify more minor issues than major ones

### Application to Student Projects

- Students will conduct peer evaluations using heuristic worksheets
- Teams must review feedback, consider severity ratings, and decide which problems to fix
- Decisions should balance severity of issues against effort required to address them
- Documentation of reasoning behind decisions is required

## **Heuristic Evaluation Assignment Instructions**

---

### Assignment Structure

- The assignment consists of two parts: Part A (conducting the evaluation) and Part B (analyzing evaluation results)
- Teams will evaluate other teams' prototypes using heuristic evaluation methods
- Each team must identify at least six issues during the evaluation

### Part A: Conducting the Evaluation

- Check group assignments under project folder for heuristic evaluation
- Contact team leaders to get prototype links and any additional documents
- Form evaluator-observer pairs within each team
- Observers must complete the heuristic testing worksheet template
- Return completed worksheets to the project teams being evaluated
- Submit: list of participants and original heuristic worksheets

### Part B: Analyzing Results

- Consolidate individual observations into a single problem list
- Summarize the evaluation findings in your own words
- Decide which identified issues to fix and which to ignore
- Provide reasoning for each decision (fix vs. not fix)
- Submit: list of participants, consolidated problem list with severity ratings, problem analysis summary, and implementation plan
